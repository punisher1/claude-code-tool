# 开发任务清单

本清单基于 `docs/2-技术设计文档.md` 制定，用于指导开发过程。请按顺序执行。

## Phase 1: 项目初始化与基础架构

- [ ] **Task 1.1: 初始化 Rust 项目**
    - [ ] 运行 `cargo new claude-code-tool` (如果尚未创建)。
    - [ ] 编辑 `Cargo.toml`，添加依赖：`clap`, `serde`, `serde_json`, `toml`, `dirs`, `anyhow`, `thiserror`, `dialoguer`, `console`, `env_logger`, `log`, `lazy_static`, `tempfile` (dev-dependencies)。
    - [ ] 创建 `src` 下的子模块文件 (`models.rs`, `config_manager.rs`, `provider_store.rs`, `claude_adapter.rs`, `utils.rs`, `commands/mod.rs`)。
    - [ ] 在 `main.rs` 中设置基础的 `env_logger` 初始化。

- [ ] **Task 1.2: 定义数据模型 (`models.rs`)**
    - [ ] 定义 `Provider` 结构体 (base_url, model map)。
    - [ ] 定义 `ConfigInstance` 结构体 (provider_ref, env vars)。
    - [ ] 定义 `AppConfig` 结构体 (providers, configs, current)。
    - [ ] **[Unit Test]**: 编写测试 `test_config_serialization`，验证 TOML 序列化/反序列化是否符合预期格式。

## Phase 2: 核心逻辑模块实现

- [ ] **Task 2.1: 实现配置管理 (`config_manager.rs`)**
    - [ ] 实现 `get_config_path()`：确定配置文件路径（支持测试时注入路径或 override）。
    - [ ] 实现 `load_config()`：读取文件，处理文件不存在的情况（返回默认值）。
    - [ ] 实现 `save_config()`：将 `AppConfig` 序列化并写入文件。
    - [ ] **[Unit Test]**: 使用 `tempfile` 测试 `test_load_save_cycle`，确保写入后能正确读取，且文件不存在时返回默认值。

- [ ] **Task 2.2: 实现 Provider 仓库 (`provider_store.rs`)**
    - [ ] 定义 `BUILTIN_PROVIDERS` 常量/静态变量，包含文档中列出的内置 Provider。
    - [ ] 实现 `get_merged_providers()`：接收用户自定义 Provider Map，返回合并后的 Map。
    - [ ] **[Unit Test]**: 编写 `test_provider_merge`，验证内置 Provider 存在，以及自定义 Provider 能正确覆盖同名内置 Provider。

- [ ] **Task 2.3: 实现 Claude 适配器 (`claude_adapter.rs`)**
    - [ ] 实现 `get_settings_path()`。
    - [ ] 实现 `update_settings(path, env_map)`：读取 JSON -> 修改 `env` -> 写入 JSON。注意参数设计要支持传入路径以便测试。
    - [ ] **[Unit Test]**: 编写 `test_update_settings_preserve_fields`，创建一个模拟的 `settings.json`（包含非 env 字段），调用更新方法，验证 `env` 被正确修改且其他字段（如 `theme`）未丢失。

## Phase 3: CLI 命令实现

- [ ] **Task 3.1: CLI 骨架 (`main.rs` & `commands/mod.rs`)**
    - [ ] 使用 `clap` 定义主命令和子命令结构 (`Provider`, `Add`, `Use`, `Remove` 等)。
    - [ ] 在 `main.rs` 中解析参数，并分发到 `commands` 模块的具体函数。

- [ ] **Task 3.2: 实现 `provider` 子命令 (`commands/provider.rs`)**
    - [ ] 实现 `list`：调用 `provider_store` 获取列表，格式化输出（区分 Built-in/Custom）。
    - [ ] 实现 `add`：
        - [ ] 使用 `dialoguer` 获取用户输入（Name, BaseURL, Models）。
        - [ ] 调用 `config_manager` 加载 -> 更新 -> 保存。
    - [ ] 实现 `rm`：
        - [ ] 检查是否为内置（不可删）。
        - [ ] 检查依赖引用。
        - [ ] 更新配置并保存。

- [ ] **Task 3.3: 实现 `add` 命令 (`commands/config.rs`)**
    - [ ] 接收参数 `alias`, `provider`, `api_key`。
    - [ ] 验证 `provider` 是否有效。
    - [ ] 在 `AppConfig.configs` 中添加新条目。
    - [ ] 保存配置。

- [ ] **Task 3.4: 实现 `use` 命令 (`commands/switch.rs`)**
    - [ ] 接收参数 `alias`。
    - [ ] 抽离核心逻辑 `generate_env_vars(config, provider)` 为独立函数，便于测试。
    - [ ] **[Unit Test]**: 测试 `generate_env_vars`，验证生成的环境变量 Map 是否包含正确的 Key 和 Value。
    - [ ] 实现主逻辑：从配置查找 -> 生成 Env Vars -> 调用 `claude_adapter::update_settings()` -> 更新 `AppConfig.current` 并保存。
    - [ ] 输出成功提示。

## Phase 4: 完善与交付

- [ ] **Task 4.0: 单元测试全量检查**
    - [ ] 运行 `cargo test`，确保所有模块的测试通过。
    - [ ] 检查测试覆盖率，对遗漏的关键逻辑补充测试。

- [ ] **Task 4.1: 集成测试**
    - [ ] 手动端到端测试流程：
        1. 运行 `cct provider list`。
        2. 运行 `cct add -p deepseek sk-test my-deepseek`。
        3. 运行 `cct use my-deepseek`。
        4. 检查 `~/.claude/settings.json` 内容。
    - [ ] 修复发现的 Bug。

- [ ] **Task 4.2: 代码清理与文档**
    - [ ] 运行 `cargo fmt` 和 `cargo clippy` 进行代码规范检查。
    - [ ] 确保 `README.md` 包含构建和使用说明。
    - [ ] 准备发布构建 (`cargo build --release`)。
